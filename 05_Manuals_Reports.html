Course Outcomes

  1. CO1: Demonstrate the use of basic Git repository commands for version control operations.
  2. CO2: Implement branch management strategies for collaborative software development.
  3. CO3: Apply collaboration techniques using remote repositories and distributed version control systems.
  4. CO4: Configure Git tags, releases, and advanced Git operations for effective project management.
  5. CO5: Modify Git history to maintain repository integrity and support project requirements.

Recommended journal rule: Students should write the Aim, Requirements, Theory, Procedure/Commands, Observations/Output, Result, Learning Outcome and Viva preparation for every experiment. Screenshots may be attached where the faculty requires evidence.

What Students Should Write in the Journal

Use this same structure for every experiment unless faculty specifies another format.

1. Aim

Write one or two sentences describing exactly what the experiment demonstrates.

2. Requirements

List Git, terminal/command prompt, text editor and remote Git platform if required.

3. Theory

Explain the Git concept used in the experiment in simple words.

4. Procedure

Write numbered steps. Include the important commands and explain what each command does.

5. Commands / Program

Write commands exactly as executed. Replace placeholders such as repository URLs or commit IDs with actual values.

6. Observation / Output

Record important terminal output and attach screenshots if required.

7. Result

State whether the required Git operation was successfully performed.

8. Learning Outcome

Write what Git skill was acquired.

Important: Do not blindly copy example commit IDs, usernames, URLs or branch names when the experiment requires values from the student's repository. Use the actual values generated during the lab.

Faculty Teaching Guide

Suggested classroom/lab flow for using the same manual as a teaching resource.

  1. Explain the concept: introduce the Git operation and why it is used.
  2. Demonstrate: execute the commands on a projected repository.
  3. Guided practice: students repeat the steps with their own repository.
  4. Verification: ask students to show command output/history/status.
  5. Journal: students write the prescribed sections and record actual observations.
  6. Viva: ask concept-based questions rather than only command memorization.
  7. Evidence: retain appropriate repository links/screenshots/records according to departmental practice.
